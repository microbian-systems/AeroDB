FilterInclude<T, TChild>(ISurrealDbQueryable<T>, Expression<Func<T, IEnumerable<TChild>>>, Expression<Func<IEnumerable<TChild>, bool>>)

Filters parent documents based on a predicate applied to their included child collection in-memory, after includes are fully loaded.

Only parent documents whose child collection satisfies the predicate are returned. Unlike a WHERE clause, this filter runs on the client side and can use any LINQ expression on the child collection (e.g., .Any(), .All(), .Count()).

Must be used after IncludeReverse<T, TChild>(ISurrealDbQueryable<T>, Expression<Func<T, IEnumerable<TChild>?>>, string) on the same property to have effect. The filter does not affect which children are loaded — it only controls which parent documents are included in results.

IncludeReverse<T, TChild>(ISurrealDbQueryable<T>, Expression<Func<T, IEnumerable<TChild>?>>, string)

Eagerly loads a collection of child records where the child has a foreign key pointing back to the parent T. Uses SurrealDB's LET variable for server-side batch loading in a single round trip.

Generated SurrealQL pattern: LET $main = (SELECT * FROM source WHERE ...); SELECT * FROM $main; SELECT * FROM `child` WHERE `fkField` IN (SELECT VALUE [id|Id] FROM $main);

Unlike Include<T,TInclude>, which is forward (FK on parent), this is reverse (FK on child). The child records are collected into a List<TChild> and set on the collection property.

Include<T, TInclude>(ISurrealDbQueryable<T>, Expression<Func<T, TInclude?>>)

Eagerly loads a typed record<T> property via an inline subquery. The subquery is embedded in the SELECT clause, using $parent to reference the parent row's foreign key field.

Generated SurrealQL pattern: SELECT *, (SELECT * FROM `target` WHERE id = $parent.fk LIMIT 1)[0] AS Property FROM `source`

This is a single-round-trip operation — no separate queries are executed. Unlike Fetch(), this does not require the SurrealDB server to support the FETCH clause and works with typed record<T> properties.
