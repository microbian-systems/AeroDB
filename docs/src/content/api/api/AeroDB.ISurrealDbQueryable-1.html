Fetch(Expression<Func<T, object?>>)

Adds a SurrealQL FETCH clause to eagerly expand a record-typed field.

SurrealDB's FETCH expands record references inline — the full referenced document is returned as part of the query result. This is a server-side operation requiring no additional round trips.

Only use this on properties typed as RecordId or RecordId?. Other property types will be silently ignored by the SurrealDB engine.

Performance: No additional round trips. The FETCH clause is appended to the generated SurrealQL. For multiple fields, call Fetch() multiple times — they accumulate.

IncludeBatch<TProperty, TInclude>(Expression<Func<T, TProperty>>, Action<TInclude>)

Eagerly loads related documents using SurrealDB's LET variable for server-side batch loading in a single round trip.

The generated SurrealQL uses a LET variable to cache the filtered main query results, then includes are resolved via subqueries against the in-memory LET variable — equivalent to PostgreSQL temp tables but using SurrealDB's native variable system.

Performance: One round trip regardless of how many Includes are chained. The main WHERE filter is evaluated once by the LET statement.

SurrealQL pattern: 

LET $main = (SELECT * FROM source WHERE ...);
             SELECT * FROM $main;
             SELECT * FROM target WHERE id IN (SELECT VALUE fk FROM $main);

IncludeBatch<TKey, TInclude>(Expression<Func<T, TKey>>, IDictionary<TKey, TInclude>)

Eagerly loads related documents into a dictionary keyed by the property value.

Like IncludeBatch<TProperty, TInclude>(Expression<Func<T, TProperty>>, Action<TInclude>), but populates an existing dictionary instead of invoking a callback. Uses SurrealDB's LET variable for server-side batch loading in a single round trip regardless of how many Includes are chained.
